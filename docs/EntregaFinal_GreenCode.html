1. Descripción del Proyecto

GreenCode es una red profesional para desarrolladores construida con Angular 19. Permite a los usuarios crear un perfil profesional, publicar contenido, conectar con otros desarrolladores, buscar empleo, enviar mensajes privados y recibir notificaciones. La aplicación está desplegada en GitHub Pages con CI/CD automatizado mediante GitHub Actions.

URL de despliegue: https://atellodev.github.io/greencode/

2. Estilos y Diseño (CSS)

La aplicación utiliza CSS personalizado con variables CSS (custom properties) para mantener consistencia visual. El tema es verde con modo oscuro forzado, inspirado en la identidad de GreenCode.

Cada componente de Angular incluye sus estilos en el decorator @Component usando la propiedad styles, garantizando encapsulación de estilos por componente.

4. Salida a Internet (Despliegue)

La aplicación se despliega automáticamente a GitHub Pages mediante GitHub Actions cada vez que se hace push a la rama main.

# .github/workflows/deploy.yml name: Deploy GreenCode to GitHub Pages on: push: branches: [main] jobs: build-and-deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 20 - run: npm ci - run: npx ng build --configuration production - uses: peaceiris/actions-gh-pages@v3 with: github_token: ${{ secrets.GITHUB_TOKEN }} publish_dir: dist/redlink/browser

Figura 11. Workflow de GitHub Actions — pipeline CI/CD que se ejecuta en cada push a main. Instala dependencias con npm ci, construye con Angular CLI, y despliega el output a GitHub Pages usando peaceiris/actions-gh-pages.

5. Lo Aprendido Durante el Proyecto

Angular 19 Standalone Components

Aprendimos a construir componentes sin NgModules, usando el decorator @Component con imports directos. Esto simplifica la arquitectura, reduce boilerplate y mejora el tree-shaking. Cada componente es autónomo y declara sus propias dependencias.

Signals para Gestión de Estado

Migramos de RxJS BehaviorSubjects a Angular signals (signal(), computed()). Las signals son más simples, síncronas, y notifican cambios solo cuando el valor realmente cambia. Los computed() derivan estado reactivamente sin suscripciones manuales.

Lazy Loading con loadComponent

Aprendimos a usar loadComponent() en lugar de loadChildren() con módulos. Cada ruta carga su componente bajo demanda, reduciendo el bundle inicial a ~83 kB transferidos. Esto mejora significativamente el First Contentful Paint.

Control Flow Nativo (@if, @for)

Utilizamos la nueva sintaxis de control flow de Angular 17+ (@if, @for, @else) en lugar de *ngIf y *ngFor. Es más legible, no requiere CommonModule, y tiene mejor performance con tracking integrado.

Integración de APIs Reales

Aprendimos a consumir APIs REST reales con HttpClient y firstValueFrom. Integramos randomuser.me para perfiles, Picsum Photos para imágenes, y DiceBear para avatares. Implementamos fallbacks graceful cuando las APIs no responden.

OAuth 2.0 con PKCE

Implementamos autenticación LinkedIn con OAuth 2.0 + PKCE (Proof Key for Code Exchange). Generamos code_verifier y code_challenge con Web Crypto API, manejamos el callback, e intercambiamos el code por access token.

CSS Variables y Tema Oscuro

Usamos CSS Custom Properties para un sistema de diseño consistente. El modo oscuro se fuerza aplicando variables en :root. Cada componente referencia variables globales (var(--surface), var(--red-600)), garantizando consistencia visual.

CI/CD con GitHub Actions

Configuramos un pipeline de despliegue continuo. Cada push a main dispara: npm ci → ng build → deploy a GitHub Pages. Aprendimos a usar secrets de GitHub, actions de terceros (peaceiris/actions-gh-pages), y cache de dependencias.

Persistencia con localStorage

Implementamos persistencia de datos en localStorage con keys versionadas. El DataService guarda automáticamente posts, conexiones, empleos, conversaciones, perfil y actividades. Al recargar, restaura el estado desde localStorage sin perder datos.

Guards Funcionales (CanActivateFn)

Aprendimos a usar la API funcional de guards de Angular 19 (CanActivateFn) en lugar de clases CanActivate. Más simple, usa inject() para dependencias, y se integra naturalmente con standalone components.

6. Experiencia

Desarrollar GreenCode fue una experiencia integral que abarcó todo el ciclo de vida de una aplicación web moderna: desde la planeación de la arquitectura hasta el despliegue en producción. El proyecto comenzó con la idea de crear una red profesional específica para desarrolladores, un nicho que LinkedIn no atiende con suficiente profundidad técnica.

La fase de planeación (Avance 2) fue fundamental para establecer una arquitectura sólida. Decidir entre standalone components y NgModules tradicionales, elegir signals sobre RxJS para estado, y planificar el lazy loading de cada ruta fueron decisiones que impactaron todo el desarrollo posterior. La estructura de servicios (AuthService, DataService, RealApiService) con responsabilidades claras facilitó enormemente el mantenimiento.

La fase de implementación trajo desafíos interesantes. La integración de OAuth 2.0 con PKCE para LinkedIn requirió entender el flujo completo de autorización, generar code challenges con la Web Crypto API, y manejar el callback correctamente. La gestión de estado con signals resultó notablemente más intuitiva que RxJS para este tipo de aplicación — los computed() eliminaron la necesidad de suscripciones manuales y el código quedó más predecible.

La integración de APIs reales (randomuser.me, Picsum Photos) le dio autenticidad a los datos seed. Ver fotos reales y nombres variados en lugar de datos de prueba genéricos elevó la calidad visual de la aplicación. Implementar fallbacks para cuando las APIs no responden fue una lección importante de resiliencia.

Los bugs encontrados durante la auditoría final fueron valiosas lecciones. El más significativo fue que el FeedComponent tenía un perfil hardcoded en inglés que no usaba el DataService — un error de copy-paste que pasó desapercibido. También descubrimos que las búsquedas en Jobs y Messaging no funcionaban porque usaban strings planos en lugar de signals, lo que rompía la reactividad de los computed(). Estos bugs enseñaron la importancia de revisar que el estado fluya correctamente a través de signals.

El despliegue con GitHub Actions fue sorprendentemente sencillo de configurar pero poderoso en su impacto. Ver la aplicación publicada automáticamente en https://atellodev.github.io/greencode/ después de cada push dio una sensación de profesionalismo y productividad que un despliegue manual nunca podría igualar.

En conclusión, el proyecto GreenCode demostró que Angular 19 con standalone components, signals, y lazy loading es una stack excepcionalmente productiva para construir aplicaciones SPA completas. La combinación de tipado estricto con TypeScript, reactividad con signals, y el ecosistema de Angular CLI resulta en código limpio, mantenible y performante. La experiencia de llevar una idea desde cero hasta producción, con CI/CD, APIs reales, y un tema visual profesional, fue invaluable como aprendizaje integral del desarrollo web frontend.
